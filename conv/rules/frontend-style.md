# 前端样式规则清单

只有规则，没有解释和示例。

## CSS Module / SCSS 项目

1. 预处理器 less / scss 二选一，同一项目内不混用。
2. 页面组件样式用 CSS Module，文件名与组件同名。
3. Module 内类名用 camelCase。
4. 页面 module 只写布局和页面独有样式，不写公共组件内部样式。
5. 公共组件禁止 CSS Module；内部类名全局，带项目前缀，用 BEM。
6. 外部调整时，在使用方页面的 module 里用 `:global` 穿透。
7. 嵌套不超过 3 层；`!important` 只用于覆盖第三方，且必须注释原因。
8. 状态类名统一用 `is-` 前缀：`is-active` / `is-disabled` / `is-loading` / `is-error`。
9. 单个 module 文件超过 150 行，考虑拆组件，但应该以组件的功能为主，不能因为 module 太长而将组件功能拆分。

## Tailwind 项目

1. Tailwind 项目页面用工具类，不写 CSS Module；复杂动画、伪元素用 SCSS。CSS Module / Less / SCSS 项目不引入 Tailwind。
2. 颜色走主题令牌（`@theme` / `theme.extend.colors`），禁止硬编码 hex；禁止 `bg-[#xxx]` 任意值。
3. 间距用 spacing scale（`p-4`、`gap-3`，1 单位 = 4px）；禁止 `p-[13px]`，非标值扩展 `theme.spacing`。
4. 多个工具类用 `cn`（`twMerge` + `clsx`）分组；类太多影响阅读时用 `cn` 拆分。
5. 响应式用断点前缀（`sm:` `md:` `lg:`），移动端优先；断点在 `theme.screens` 定义。
6. 交互状态用前缀（`hover:` `focus:` `active:` `disabled:`），不写伪类 CSS。
7. `@apply` 只用于提取多处复用的工具类组；单处不 `@apply`。
8. 多主题用主题机制；深色模式也是主题，禁止用 `dark:` 前缀。引入的第三方/生成组件若自带 `dark:` 变体，应清理成令牌。
9. shadcn-ui：默认生成的组件在其上拼接出项目级基础组件供全局使用；不同用途直接用默认导出的组件拼接，不塞进项目级组件。
10. shadcn 已有对应组件时必须用它，不要自己造轮子，只有 shadcn 没有的才新建；新建的组件不乱封装成项目级组件。
11. 字号只用刻度里已有的类名，禁止 `text-[13px]` 这类任意值；设计稿是非标值时取最接近的档位，不要新增非标档位。换档位造成的对不齐，优先用 flex 居中解决，而不是补固定数值。

## 通用（两者均适用）

1. 基于 Tailwind 的组件库（shadcn/ui 等）不适用「有组件库就不引入 Tailwind」的旧约定；与非 Tailwind 组件库混用时，以 Tailwind 项目的规则为准。
2. 公共组件根元素建议带组件级类名（如 `xx-save-btn`）作为唯一对外样式入口，有项目前缀则加前缀；Tailwind 项目可选，对外入口即 `className`。
3. 穿透只允许改表现属性（颜色、字号、间距、圆角），不允许改布局结构。
4. 重封装组件库组件时根元素带前缀类名；禁止直接改第三方内部 class。
5. 改样式只允许三种手段，按优先级：theme token → 重封装 → 页面穿透。
6. 全局样式只允许一个文件；由应用入口（根组件）引入，业务组件内不得再引入全局 css。
7. design token 集中在全局样式/主题配置里；组件内禁止写死颜色值。Canvas 等只能接收字面量颜色的场景，令牌仍定义在全局样式，运行时读取。
8. 禁止行内 `style`，动态计算值除外。
9. 公共组件文件头建议声明"可覆盖的类名"；Tailwind 项目可选，理由同第 2 条。
10. 断点集中定义，页面里禁止裸写媒体查询数值。
11. 间距等一系列数值默认取 2 或 4 的倍数；因 border 出现单数时，优先用 flex 解决，解决不了才允许固定数值兜底。
12. 样式里不写魔法数字，间距与字号走令牌或 2/4 的倍数。
